# Product listing frontend contract

The `/shop` route currently renders local mock data. This document describes the
normalized model consumed by the frontend and the current filtering and sorting
behavior. It is not the raw schema of a standard Shopware Store API response.

When the backend is ready, an integration layer must map Shopware products,
associations, calculated prices, and properties into this model. The current
mock is located in `src/lib/shopware/mocks/product-listing.ts`.

The current contract is enforced at TypeScript compile time. Runtime parsing of
an unknown Store API response will be added together with the backend adapter.

## Listing shape

```json
{
  "currency": "EUR",
  "description": "Considered furniture for living and dining spaces.",
  "eyebrow": "The full collection",
  "locale": "de-DE",
  "title": "Furniture collection",
  "products": [
    {
      "id": "alba",
      "name": "Alba Modular Sofa",
      "description": "Natural boucle, 4 seats",
      "url": "/product/alba",
      "image": {
        "url": "/images/hero-living.webp",
        "alt": "Alba modular sofa in a warm living room"
      },
      "badge": "Bestseller",
      "unitPrice": 2490,
      "previousPrice": 2890,
      "category": "sofas",
      "categoryLabel": "Sofas",
      "company": "JV Studio",
      "material": "Boucle",
      "colors": [
        {
          "value": "cream",
          "label": "Cream",
          "hex": "#ded6c8"
        }
      ],
      "sizes": ["large", "extra-large"],
      "createdAt": "2026-02-04",
      "featuredRank": 0,
      "rating": 4.9,
      "reviewCount": 128
    }
  ]
}
```

## Listing fields

All listing fields are currently required.

| Field         | Rule                                                                                                |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `currency`    | ISO 4217 currency code used to format every product price.                                          |
| `locale`      | Locale used by `Intl.NumberFormat`, for example `de-DE`.                                            |
| `title`       | Main `/shop` page heading.                                                                          |
| `eyebrow`     | Short label displayed above the heading.                                                            |
| `description` | Introductory text displayed beside the heading.                                                     |
| `products`    | Array of normalized products. It must contain at least one product with the current implementation. |

The Administration source for `title`, `eyebrow`, and `description` has not
been selected yet. The backend may later resolve them from category content, a
CMS page, or a dedicated storefront configuration without changing the product
shape.

## Product fields

| Field           | Required | Rule and suggested Shopware source                                                                                |
| --------------- | -------- | ----------------------------------------------------------------------------------------------------------------- |
| `id`            | Yes      | Stable product identifier.                                                                                        |
| `name`          | Yes      | Translated product name.                                                                                          |
| `description`   | Yes      | Short plain-text card description.                                                                                |
| `url`           | Yes      | Storefront product URL generated by the backend integration.                                                      |
| `image.url`     | Yes      | Resolved cover media URL.                                                                                         |
| `image.alt`     | Yes      | Accessible media description, with a product-name fallback applied by the backend.                                |
| `badge`         | No       | Short merchandising label such as `New` or `Sale`; its Administration source is not defined yet.                  |
| `unitPrice`     | Yes      | Current calculated sales-channel price in major currency units.                                                   |
| `previousPrice` | No       | Previous/list price. A discount percentage is shown only when it is greater than `unitPrice`.                     |
| `category`      | Yes      | Stable normalized category value used by the filter. The current model supports one listing category per product. |
| `categoryLabel` | Yes      | Translated category name displayed in the filter.                                                                 |
| `company`       | Yes      | Translated manufacturer/company name.                                                                             |
| `material`      | Yes      | Translated material value. The current model supports one material per product.                                   |
| `colors`        | Yes      | Array of normalized color options.                                                                                |
| `sizes`         | Yes      | Array containing only `small`, `medium`, `large`, or `extra-large`.                                               |
| `createdAt`     | Yes      | ISO 8601 date or timestamp. All values must use a consistent ISO format for newest-first sorting.                 |
| `featuredRank`  | Yes      | Numeric ascending rank used by the default `featured` sort. Its Administration source is not defined yet.         |
| `rating`        | No       | Numeric rating displayed with one decimal place and used by the best-rated sort.                                  |
| `reviewCount`   | No       | Number of reviews. It is displayed only when `rating` is also present.                                            |

Each color requires a stable `value`, a translated `label`, and a valid CSS
color in `hex`. Shopware product properties are the expected source for color,
material, and size. If the standard property option does not contain a color
code, the backend must resolve it from an agreed custom field or mapping.

Prices are currently displayed without fraction digits. The frontend derives
the listing currency and locale from the top-level object, not from individual
products.

## Images and links

- Mock product images use root-relative paths from `public/images`.
- The production media host is intentionally not configured yet.
- Do not change `next.config.ts` or the `next/image` settings until the Shopware
  media storage and delivery host are agreed.
- A remote product image URL must not be enabled by silently broadening the
  allowed Next.js image hosts.
- Product URLs should be internal storefront paths. Product detail routes are
  outside the scope of the current `/shop` implementation.

## Filters

The frontend derives filter options and their product counts from the complete
`products` array. The backend does not currently send a separate aggregation
object.

| Filter   | Matching rule                                                   |
| -------- | --------------------------------------------------------------- |
| Colour   | `colors` must contain at least one selected color value.        |
| Price    | `unitPrice` must be inside the inclusive `from` and `to` range. |
| Company  | `company` must equal one of the selected companies.             |
| Size     | `sizes` must contain at least one selected size value.          |
| Category | `category` must equal one of the selected categories.           |
| Material | `material` must equal one of the selected materials.            |

Selections inside one filter group use OR logic. Different filter groups are
combined with AND logic. Empty groups do not restrict the result.

The initial price bounds are calculated from the lowest and highest
`unitPrice`, rounded outward to multiples of 10. The two numeric inputs clamp
their values to the available range and to each other; there is no price
slider.

### Request loading state

- `ShopCatalog.isLoading` must reflect the real pending state of the product
  request. The frontend does not add an artificial loading delay.
- While a request is pending, only the product results area is dimmed and
  covered by its local loading indicator. Filters and the rest of the page
  remain available.
- When `isLoading` changes from `true` to `false`, the frontend smoothly scrolls
  to the beginning of the updated product grid.
- Local mock filtering is synchronous, so the mock route keeps `isLoading`
  disabled.

### Long option lists

- Colour, company, size, category, and material initially show at most eight
  options.
- If a group contains more than eight options, `Show all` expands it and
  `Show less` collapses it again.
- An expanded list has a fixed maximum height and becomes scrollable.
- Company additionally displays a small case-insensitive search field after it
  is expanded.
- Colour, size, category, and material do not currently display a search field.
- Filter group order, labels, the eight-option limit, and search availability
  are frontend constants and are not Administration-controlled.

## Sorting

The frontend currently provides these fixed options:

| Value              | Behavior                                                  |
| ------------------ | --------------------------------------------------------- |
| `featured`         | `featuredRank` ascending; this is the default.            |
| `newest`           | `createdAt` descending.                                   |
| `price-ascending`  | `unitPrice` ascending.                                    |
| `price-descending` | `unitPrice` descending.                                   |
| `rating`           | `rating` descending; a missing rating is treated as zero. |

The option labels, order, and default value are not currently controlled by
Shopware Administration. Filtering and sorting are performed in the browser on
the complete mock array. The real Store API integration may move these
operations to Shopware for pagination and large catalogs, but it must preserve
the documented UI values or introduce an explicit replacement contract.

## Administration responsibility boundary

Once the Store API adapter exists, Shopware Administration is expected to
control the underlying catalog data:

- product activation, visibility, names, descriptions, and associations;
- sales-channel prices and list prices;
- cover media and accessible media metadata;
- manufacturers used as companies;
- categories;
- product properties used for colors, sizes, and materials;
- review data when Shopware reviews are enabled.

The following behavior remains controlled by the frontend until a separate
listing configuration contract is introduced:

- visual styling of filters, checkboxes, and the sort select;
- filter group order and labels;
- the eight-option preview limit;
- which groups provide search;
- sorting labels, order, and default selection;
- badge and `featuredRank` Administration mapping;
- the Administration source of the page title, eyebrow, and description.

## Backend checklist

1. Fetch products for the active sales channel with the required price, cover,
   manufacturer, category, property, and review associations.
2. Map the Store API result into the normalized listing and product fields
   documented above.
3. Agree which Shopware property groups represent color, size, and material,
   including the source of each color code.
4. Normalize size values to the four supported frontend values.
5. Select one listing category and one material when a Shopware product has
   multiple matching values, or agree a future multi-value contract change.
6. Define Administration sources for badges, featured rank, and page copy if
   those fields must be editable.
7. Agree the production media host before changing Next.js image settings.
8. Replace the local mock only after the adapter, error handling, and pagination
   strategy are ready.
