# UX-архитектура storefront JVMöbel

Дата: 3 сентября 2026 года.

## Статус документа

Проект находится на ранней стадии, поэтому отсутствие большинства страниц и маршрутов сейчас является ожидаемым, а не ошибкой. Этот документ описывает целевую логику будущего сайта: структуру страниц, назначение кнопок, переходы между сценариями и рекомендуемый состав главной.

Цель — заранее определить непрерывный путь пользователя, чтобы новые страницы и CMS-блоки создавались как части одной системы.

## 1. Цели storefront

Сайт должен решать пять основных задач:

1. Быстро объяснить ассортимент и характер бренда JVMöbel.
2. Помочь найти мебель через поиск, категории, комнаты и вдохновение.
3. Дать достаточно информации и доверия для дорогой покупки.
4. Провести пользователя от товара до оплаты без лишних препятствий.
5. Поддержать клиента после покупки: заказ, доставка, возврат и расторжение договора.

Главный пользовательский путь:

`Главная → Категория или поиск → Карточка товара → Корзина → Checkout → Подтверждение → Заказ в аккаунте`

Альтернативные пути:

- `Главная → Räume → Категория → Товар`;
- `Главная → Wohnideen → Shoppable Look → Товар`;
- `Поиск → Результаты → Фильтры → Товар`;
- `Wishlist → Товар → Корзина`;
- `Заказ → Доставка / возврат / Widerruf`.

### Основные страницы

## 3. Логика глобального Header

### Логотип

- Всегда ведёт на `/`.
- На главной повторный клик возвращает пользователя к началу страницы.
- Доступное название: `JVMöbel Startseite`.

### Kategorien

- Открывает меню верхнего уровня без перехода.
- Категория с дочерними элементами открывает следующий уровень меню.
- `Alle Artikel in … ansehen` ведёт на landing page текущей категории.
- Конечная подкатегория ведёт на соответствующую product listing page.
- URL берётся из Shopware navigation, а не собирается внутри UI-компонента.

### Основная навигация

| Пункт        | Куда ведёт             |
| ------------ | ---------------------- |
| Neuheiten    | `/shop?collection=new` |
| Wohnzimmer   | категория Wohnzimmer   |
| Sofas        | подкатегория Sofas     |
| Sessel       | подкатегория Sessel    |
| Esszimmer    | категория Esszimmer    |
| Schlafzimmer | категория Schlafzimmer |
| Stauraum     | категория Stauraum     |
| Angebote     | `/shop?promotion=sale` |

Desktop-навигация и мобильное меню должны использовать один источник Shopware navigation.

### Поиск

1. Пользователь вводит запрос.
2. После 2–3 символов можно показывать подсказки товаров и категорий.
3. Enter или кнопка переводят на `/shop?query=<значение>`.
4. Каталог читает `query` на сервере и запрашивает Shopware search listing.
5. Запрос остаётся видимым в поисковом поле и URL.
6. Фильтры, сортировка и пагинация сохраняют `query`.
7. При отсутствии результатов показываются исправление запроса, популярные категории и возможность очистить фильтры.

### Kundenkonto

- Для гостя ведёт на `/account/login`.
- Для авторизованного клиента ведёт на `/account` и показывает его имя.
- После входа пользователь возвращается к исходному сценарию, например checkout или wishlist.

### Wunschliste

- Ведёт на `/wishlist`.
- Для гостя товары сохраняются локально или через гостевой Shopware context.
- При авторизации локальный список объединяется со списком аккаунта.
- Иконка может показывать количество сохранённых товаров.

### Warenkorb

- Клик открывает mini-cart drawer с последними товарами.
- Внутри доступны изменение количества, удаление и сумма.
- `Warenkorb ansehen` ведёт на `/cart`.
- `Zur Kasse` ведёт на `/checkout`.
- На мобильном допустим прямой переход в `/cart`.
- Иконка показывает реальное количество позиций.

До реализации account, wishlist или cart соответствующее действие лучше скрывать, а не вести на временную страницу с другим смыслом.

## 4. Целевая логика главной страницы

### 4.1 Hero — оставить

Hero создаёт первое впечатление и направляет в основной ассортимент.

**Основной CTA:** `Kollektion entdecken` → `/shop` либо на активную CMS campaign landing page.

**Вторичный CTA:** `Nach Räumen entdecken` → `#raeume`.

Если Hero посвящён конкретной акции, текст и ссылка должны приходить из CMS. Одновременно не следует показывать две кнопки с почти одинаковым назначением.

Визуально рекомендуется сохранить крупную фотографию, но заменить чёрный overlay тёплым коричнево-оливковым градиентом. Это поддержит мягкий характер дизайна и сохранит контраст текста.

### 4.2 Beliebte Kategorien — добавить

6–8 компактных категорий: Sofas, Sessel, Esstische, Betten, Schränke, Lampen, Kommoden, Gartenmöbel.

Каждая карточка ведёт на product listing соответствующей категории. Данные, изображение, порядок и URL приходят из CMS/Shopware.

Этот блок отвечает на вопрос «какой предмет мне нужен», поэтому не дублирует Räume.

На desktop — компактная сетка. На мобильном — горизонтальный scroll-snap с видимой частью следующей карточки.

### 4.3 Räume — оставить

Блок отвечает на вопрос «какую комнату я хочу оформить» и остаётся главным необычным визуальным элементом страницы.

| Карточка     | Назначение                    |
| ------------ | ----------------------------- |
| Wohnzimmer   | category landing Wohnzimmer   |
| Esszimmer    | category landing Esszimmer    |
| Schlafzimmer | category landing Schlafzimmer |

В секцию нужно добавить `id="raeume"`, чтобы вторичная Hero-кнопка могла прокрутить к ней страницу.

На мобильном рекомендуется одна крупная featured-карточка и две более компактные, чтобы блок не занимал несколько экранов подряд.

### 4.4 Produktauswahl — оставить

Блок показывает 4–6 реальных товаров, выбранных Shopware merchandising или CMS.

- клик по фотографии или названию ведёт на product detail page;
- `Alle Produkte ansehen` ведёт на `/shop`;
- badge, цена, скидка, рейтинг и availability показываются только из реальных данных;
- при недоступном товаре карточка остаётся доступной, но явно показывает статус;
- mock-рейтинги не должны попадать в production;
- порядок товаров должен быть управляемым из CMS.

На главной не нужен полноценный `Add to cart`, если товар имеет варианты. Для простого товара допустима быстрая кнопка, но она не должна перегружать editorial-дизайн.

### 4.5 Warum JVMöbel — добавить

Три подтверждённых преимущества магазина:

| Карточка                             | Действие                                  |
| ------------------------------------ | ----------------------------------------- |
| Lieferung bis in die Wohnung         | `/service/delivery`                       |
| Aufbauservice auf Wunsch             | `/service/assembly`                       |
| Sicher bezahlen & persönlich beraten | `/service/payment` или `/service/contact` |

Если короткого описания достаточно, вся карточка может быть неинтерактивной, а секция должна иметь один CTA `Alle Services` → `/service`.

Для необычной подачи использовать крупные номера `01–03`, много свободного пространства и небольшие предметные иллюстрации вместо стандартных круглых иконок.

Показывать можно только услуги, которые JVMöbel действительно предоставляет.

### 4.6 Wohnideen aus echten Interieurs — добавить

Editorial-коллаж из 4–5 интерьеров. Каждый интерьер является shoppable look:

1. Клик открывает страницу `/inspiration/[slug]`.
2. Страница показывает фотографию и товары, использованные в интерьере.
3. Каждый товар ведёт на собственную product detail page.
4. Если отдельные look-pages пока не реализованы, карточка ведёт в наиболее релевантную категорию.

Ссылка в Instagram может быть дополнительной, но основной путь должен оставаться внутри магазина.

Визуально использовать асимметричную masonry-композицию, мягкие подписи и появление `Look entdecken` при hover/focus.

### 4.7 Newsletter — оставить

Newsletter расположен после доверия и вдохновения, когда пользователь уже понимает ценность магазина.

Логика:

1. Клиент вводит email.
2. Frontend и server action валидируют адрес.
3. Shopware создаёт newsletter recipient.
4. Клиент получает double opt-in письмо.
5. UI сообщает, что нужно подтвердить адрес, а не обещает готовую подписку раньше времени.
6. Под формой находится короткий текст со ссылкой на `/legal/privacy`.

После успешной отправки форма заменяется спокойным confirmation state без перезагрузки страницы.

### 4.8 Footer — сократить, но сохранить

Footer должен помогать завершить задачу, а не повторять всю главную.

Рекомендуемая структура:

- короткий About: 2–3 предложения и ссылка `/about`;
- 6–8 ключевых категорий и `Alle Kategorien` → `/shop`;
- Service: Lieferung, Zahlung, Kontakt, Rückgabe, Widerruf;
- Legal: Impressum, Datenschutz, AGB;
- логотипы оплаты без переходов;
- социальные ссылки в новой вкладке с безопасным `rel`;
- copyright.

Большой текущий текст About следует перенести на `/about`. Кнопку `Vertrag widerrufen` лучше разместить рядом с Service, а не делать главным CTA брендового блока.

## 6. Product listing page

Каталог является центральной страницей discovery.

### URL как источник состояния

Пример:

`/shop/wohnzimmer/sofas?query=ecksofa&color=beige&material=samt&priceTo=2500&sort=price-asc&page=2`

В URL должны храниться:

- поисковый запрос;
- категория;
- выбранные фильтры;
- сортировка;
- страница пагинации.

Это позволяет возвращаться назад без потери состояния, делиться ссылкой и корректно работать с server rendering.

### Поведение

- фильтры desktop находятся слева, mobile — в drawer;
- количество результатов обновляется после применения фильтров;
- выбранные фильтры видны как removable chips;
- `Alle Filter löschen` возвращает базовую категорию или поиск;
- сортировка не сбрасывает фильтры;
- при возврате с товара восстанавливаются позиция прокрутки и состояние listing;
- empty state предлагает удалить отдельные фильтры, а не только начать заново;
- loading state сохраняет размеры карточек, чтобы интерфейс не прыгал.

## 7. Product detail page

Карточка товара должна содержать:

1. Галерею изображений и zoom.
2. Название, бренд, SKU и реальные отзывы.
3. Текущую цену, list price и условия налогообложения/доставки.
4. Выбор варианта: размер, цвет, материал или конфигурация.
5. Availability и понятный срок доставки.
6. Количество и `In den Warenkorb`.
7. `Zur Wunschliste hinzufügen`.
8. Краткие преимущества доставки, сборки, оплаты и возврата.
9. Размеры, материалы, уход и документы.
10. Рекомендации и недавно просмотренные товары.

`In den Warenkorb` активируется только после выбора обязательного варианта. После добавления открывается mini-cart с возможностью продолжить покупки или перейти к checkout.

## 8. Корзина и checkout

### Cart

- изменение количества;
- удаление и перенос в wishlist;
- выбранные варианты товара;
- availability и срок доставки для каждой позиции;
- стоимость товаров, скидка, доставка и итог;
- промокод, только если функция реально поддерживается;
- CTA `Zur Kasse` → `/checkout`;
- secondary action `Weiter einkaufen` → последний listing или `/shop`.

Корзина гостя хранится через Shopware context token в защищённой cookie и сохраняется между визитами в разумных пределах.

### Checkout

Рекомендуемые этапы:

1. Kontakt & Adresse.
2. Lieferung.
3. Zahlung.
4. Prüfen & Bestellen.
5. Bestätigung.

Guest checkout должен быть основным доступным вариантом. Создание аккаунта предлагается после ввода данных или после заказа, но не блокирует покупку.

Перед финальным подтверждением пользователь видит полный состав заказа, адрес, доставку, оплату, итоговую сумму и обязательные юридические согласия.

## 9. Account, заказы и сервис после покупки

В аккаунте клиент может:

- видеть статус и историю заказов;
- открывать детали доставки;
- скачивать документы;
- повторять заказ;
- инициировать возврат или рекламацию;
- менять адреса и данные профиля;
- управлять wishlist и newsletter.

Widerruf должен иметь каноническую страницу `/service/revocation` с юридической информацией. Существующая модалка может быть быстрым входом в тот же процесс. Формирование email является fallback-вариантом; при появлении backend endpoint предпочтительнее отправлять форму на сервер и показывать номер обращения.

## 10. Обязательные состояния интерфейса

Каждая страница и действие должны иметь:

- loading или skeleton state;
- empty state;
- recoverable error state с повторной попыткой;
- корректный not-found для неизвестного товара или категории;
- disabled/pending state для повторной отправки формы;
- понятное подтверждение успешного действия;
- сохранение введённых данных при временной ошибке;
- доступное управление с клавиатуры и видимый focus;
- объявления динамических результатов через `aria-live`, где это необходимо.

## 11. Мобильная логика

- Header показывает menu, search и cart; второстепенные действия доступны внутри меню.
- Hero содержит основной CTA в первом экране без внутреннего скролла.
- Beliebte Kategorien использует scroll-snap.
- Räume не превращается в три очень высокие карточки подряд.
- Product listing открывает фильтры в drawer и показывает количество активных фильтров.
- На product page CTA добавления в корзину может быть sticky в нижней части экрана.
- Mini-cart и checkout учитывают safe-area устройства.
- Все интерактивные цели имеют размер не менее 44 × 44 px.
- Модалки используют `100dvh` и допускают резервную прокрутку при открытой клавиатуре.

## 12. Визуальный язык

Чтобы дизайн оставался привлекательным и необычным:

- использовать ivory, sand, sage и terracotta вместо чёрных поверхностей;
- сохранить крупную типографику и editorial-фотографии;
- строить уникальность на асимметрии, масштабе и свободном пространстве;
- не превращать все секции в одинаковые белые карточки с круглыми иконками;
- чередовать спокойные информационные блоки и насыщенные изображения;
- использовать один сильный акцент в пределах секции;
- применять анимации только как обратную связь;
- соблюдать единые tokens, контейнеры, радиусы и вертикальный ритм;
- не копировать тексты, изображения или композицию home24 буквально.

## 13. CMS и Shopware

Существующие CMS-блоки следует сохранить:

- `jv-hero`;
- `jv-room-grid`;
- `jv-product-grid`;
- `jv-newsletter`.

Новые блоки:

- `jv-category-rail` — Beliebte Kategorien;
- `jv-service-benefits` — Warum JVMöbel;
- `jv-inspiration-grid` — Wohnideen.

CMS управляет контентом, порядком, изображениями и ссылками. Shopware Store API остаётся источником товаров, цен, availability, навигации, корзины, customer state и checkout. UI-компоненты не должны самостоятельно собирать SEO URL или работать с сырыми Shopware responses.

## Источник UX-референса

Структура главной страницы [home24](https://www.home24.de/) использована как функциональный референс для быстрых категорий, сервисных преимуществ и inspiration-контента. Копировать их тексты, изображения и визуальную композицию не предлагается.
